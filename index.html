Installing Dotcom EDI Harness

This guide walks you through running the Dotcom EDI Harness Web UI on your own machine. It covers prerequisites, cloning the source, building the native helpers, and launching the agent from a local browser.

What is Dotcom EDI Harness?

Dotcom EDI Harness is a plugin-based agent runtime for running coding agents against a real project workspace. It ships as an open source toolkit you build from source — you get the CLI, the browser UI, the plugin system, and full auditability of every agent run.

The harness composes everything through a small set of pluggable capabilities. Instead of one hard-coded assistant, you get an environment you can shape:

Plugin architecture

Models, tools, skills, sessions, storage, and the UI are all interchangeable plugins.

Full coding agent

Edit files, run commands, search the web, and plan multi-step tasks against a workspace.

Sandboxed by default

Operations that require approval are gated, and every run is recorded to a session log.

Multiple profiles

Run in web, headless, sdk, or acp mode without changing your setup.

This guide installs the source build. When you finish, you'll have:

  • A local checkout of Dotcom EDI Harness at ./dotcom-edi-harness
  • Node dependencies and the native sandbox helper built
  • The browser UI serving at http://127.0.0.1:3080
  • Your first agent session ready to run against a workspace
Who this is for: developers who want to run the harness locally, inspect the code, and extend it with their own plugins. You don't need prior experience with the harness, but you should be comfortable with a terminal, git, and Node.js.

Requirements

Before you start, confirm your machine meets the following:

RequirementValueNotes
Operating system macOS, Linux, or WSL on Windows Native components build only on macOS and Linux. Plain Windows is not supported.
Node.js ^22.19.0 or >=24.0.0 Node 23 is not supported.
pnpm 11.7.0 Pinned by the packageManager field.
C compiler macOS: Xcode Command Line Tools
Linux / WSL: build-essential and musl-tools		 Linux needs musl-gcc to build the static sandbox helper.

Check what you already have:

node -v
pnpm -v

Step 1 — Get the source

Clone the repository and move into it:

git clone https://github.com/dotcom-edi/dotcom-edi-harness.git
cd dotcom-edi-harness

The checkout must include its .git directory. The build stamps the browser bundle with the source commit hash, so a directory without Git metadata cannot be built. This is why cloning is preferred over downloading an archive.

Step 2 — Install pnpm

Dotcom EDI Harness pins pnpm to a specific version. Install it globally:

npm install -g pnpm@11.7.0
pnpm -v          # expect 11.7.0

If your shell reports a different version, your PATH is probably pointing at an older global install. Open a new shell or re-check with which pnpm.

Step 3 — Install the compiler toolchain

Some parts of the harness are native code. Install the compiler for your platform:

# macOS
xcode-select --install
# Linux / WSL (Debian, Ubuntu)
sudo apt update && sudo apt install -y build-essential musl-tools

Step 4 — Install dependencies

Install everything with pnpm:

pnpm install

On a slow or unstable connection, extend the fetch timeouts and lower concurrency:

pnpm install --network-concurrency=4 --fetch-timeout=600000 --fetch-retries=5

Warnings about Unsupported platform: wanted arm64 and deprecated subdependencies are expected — they refer to optional packages for other platforms.

Step 5 — Build

Compile the native helpers, the TypeScript libraries, and the client bundles the Web UI is served from:

pnpm run build

This takes several minutes. The build is mandatory before the first launch. A successful build ends with a line like:

build: recorded <number> client artifact(s) with <number> public value(s)

Confirm the client bundles exist:

ls packages/client/ui-chat/lib/client.js

If that reports No such file or directory, the build did not complete — re-run it before continuing.

Step 6 — Start the Web UI

Launch the browser UI:

pnpm dce web

The Web UI opens at http://127.0.0.1:3080 by default.

Options

FlagEffect
--no-openDo not open a browser (use on a remote or SSH session)
--port <port>Listen on another port. --port 0 lets the OS pick a free one
--host <host>Bind host. 0.0.0.0 is deliberately rejected for safety
--trusted-host <authority>Extra authority the browser-trust fence accepts (repeatable)
--helpShow the Web app's own flags

An SSH launch prints the host URL instead of opening a browser, because the SSH client or editor owns the forwarded address.

Step 7 — First-run setup

With the Web UI open, there are three things to do before your first task:

  1. Open Settings → Models, enter your provider API key, and save. The model route becomes usable immediately, with no restart.
  2. Choose Choose workspace and select the project directory the agent should work in. The session composer stays unavailable until a workspace is selected.
  3. Start a session and send a task.
Tip: start with a small, well-scoped task the first time — for example, "Summarize this repository and identify its main packages." It gives you a feel for how the agent plans and calls tools before you point it at something larger.

Other entry modes

Web is one profile among several. The launcher selects a profile with --profile, and dce web is an alias for --profile web.

CommandPurpose
dce webServe the browser UI (alias of --profile web)
dce --profile headless "job"Run one session, print the final answer, and exit
dce --profile sdkServe SDK clients over JSON-RPC stdio
dce --profile sdk-minimalServe SDK clients with the standalone minimal agent tree
dce --profile acpServe automation clients over ACP stdio
dce --profile <name>Boot a profile under $DCE_HOME/profiles/<name>
dce plugin --profile <name> <pnpm args>Manage a profile's plugins

web, headless, sdk, sdk-minimal, and acp initialise themselves on first use. The invoking directory is the default workspace root.

Configuration

Dotcom EDI Harness keeps its state under your home directory:

PathContents
~/.dce/config.yamlHarness configuration
~/.dce/.credentials.yamlStored credentials
~/.dce/profiles/Boot profiles

Set DCE_HOME to relocate all of the above.

Stopping and restarting

Stop the server with Ctrl + C.

To start it again, no rebuild is required:

cd dotcom-edi-harness
pnpm dce web

Re-run pnpm run build only after changing source code.

musl-gcc: not foundsudo apt install musl-tools
Unsupported engineThe Node version is outside ^22.19.0 || >=24.0.0
build: system binaries are built on Linux or macOSRunning on plain Windows. Use WSL
ERR_PNPM_OUTDATED_LOCKFILERun pnpm install --no-frozen-lockfile
Port 3080 already in usepnpm dce web --port 3081
Build stops with an errorRe-run pnpm run build; build outputs are disposable and regenerated
An updated UI does not appearHard-refresh the browser (Cmd + Shift + R). Tabs, titles and favicons are cached aggressively

Quickstart

Once the requirements are met, the whole sequence is:

git clone https://github.com/dotcom-edi/dotcom-edi-harness.git
cd dotcom-edi-harness
pnpm install
pnpm run build
pnpm dce web

Install from npm

The npm packages are published under our project scope. Once available, you'll be able to launch the Web UI without cloning the source:

npx @dotcomai/dce web

If npx reports that the package cannot be found, the npm release has not gone out yet — use the source install above in the meantime.
